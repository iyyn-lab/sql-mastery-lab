# SQL Mastery Lab

A structured, hands-on learning repository for **SQL, Relational Database Engineering, and Cloud Database Management**.

The goal of this repository is to build practical database skills step by step: start with relational database fundamentals, practise SQL using a realistic e-commerce database, understand database internals, and gradually progress towards production and cloud database engineering.

## Learning Scope

- **Relational databases:** MySQL and PostgreSQL
- **SQL:** Fundamentals through advanced querying and optimization
- **Database engineering:** Schema design, normalization, transactions, concurrency, indexes, performance, security, and administration
- **Cloud database engineering:** Managed relational databases, deployment, connectivity, migration, backup, monitoring, high availability, and recovery
- **Infrastructure and integration:** Terraform fundamentals, backend application connectivity, and database automation

> The common SQL concepts come first. MySQL- and PostgreSQL-specific comparisons are intentionally deferred until Phase 16. This roadmap focuses on relational databases and does not include a NoSQL learning track.

## How We Will Learn

Each important concept will follow this learning process:

1. Technical definition and fundamentals.
2. Why the concept is required and what problem it solves.
3. Internal working and execution flow.
4. Architecture diagrams and illustrations.
5. Practical examples using sample tables and data.
6. Hands-on SQL queries with expected outputs.
7. Real-world backend and database scenarios.
8. Performance considerations, limitations, and common mistakes.
9. Independent practical assignments.
10. Knowledge assessment and the ability to explain the concept clearly.

## Practical Learning Rules

- Learn one topic at a time and do not skip prerequisites.
- Understand the concept before memorizing SQL syntax.
- Practise queries independently instead of only reading solutions.
- Use a gradually growing relational e-commerce database for examples and exercises.
- Keep SQL scripts runnable and organize them by phase and topic.
- Record expected results and observations for practical experiments.
- Test joins, transactions, indexes, and query plans instead of relying on assumptions.
- Move to the next topic only after the current topic is understood and practised.
